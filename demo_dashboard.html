What the system solves

Procurement teams need faster reviews without risking bad spend.

This system monitors item stock, checks supplier quotes, and drafts a requisition only when the facts are valid. A human approval gate keeps every step accountable and prevents silent or unsafe purchases.

Problem
Manual reorder checks are slow, inconsistent and risky.

Teams often review stock, quotes and approvals in fragmented ways, which creates delays and error-prone decisions.

Solution
One bounded workflow that validates the facts before drafting anything.

The app checks stock thresholds, compares quotations and keeps a clear approval point for the actual decision-maker.

Outcome
Faster preparation, clearer auditability, lower operational risk.

The system helps teams respond quickly while preserving traceability and control over each step.

How the system works

CheckReads stock thresholds and item status before anything is proposed.
CompareFetches valid supplier quotations and filters expired or invalid offers.
ApproveCreates a draft requisition and waits for a human confirmation before routing.

Architecture

A bounded loop with deterministic control. The model explains; the system decides safely.

Agent pipeline

SenseRead CSV, apply guardrails
PlanPython picks the next tool
ActRun tool, gate high-impact calls
ObserveUpdate state, write JSONL trace
StopGoal complete, or re-plan

Maximum 8 iterations and 2 recovery attempts, so the loop cannot run away.

The four approved tools

get_reorder_status

Read-only. Returns needs_reorder and deficit.

get_supplier_quotations

Read-only. Returns the quotations on file.

create_requisition_draft

Local draft write. Checks quantity, quote ownership and expiry.

route_requisition_for_approval

Needs an explicit human y. Status becomes PENDING_APPROVAL. Never issues a PO.

AI boundary matrix

Python owns

  • Reorder threshold comparison
  • Quote expiry validation
  • Tool allow-list
  • Role authorization
  • Stop conditions and iteration limits
  • Requisition draft writing

Gemini owns

  • Supplier comparison text
  • Risk flags
  • MOQ cash impact explanation
  • RAG policy grounding
  • Tool selection intent

Gemini never

  • Decides to reorder
  • Selects the winning supplier
  • Issues payment or a PO
